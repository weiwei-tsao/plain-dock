# Markdown 编辑器与预览色彩规范

状态：已确认，作为实现与验收的设计约束。2026-09-16。

适用范围：Markdown 正文区域，包括编辑器和预览。应用导航、按钮及成功／错误提示沿用现有规范。`.claude/rules/styling.md` 引用本规范作为 Markdown 内容层的约束；应用样式尚待实现。

## 目标与方向

让正文、列表、代码一眼可分，同时适合长文阅读。编辑和预览对同一种内容使用相同的语义色；切换视图改变排版与语法标记的显示，不改变颜色含义。

**Content is neutral, structure is indigo, literals are amber.**

采用「灰白正文 + 靛蓝结构与链接 + 琥珀代码」。保留应用现有的 zinc/indigo 基础，为代码增加独立的 amber 内容色。标题表达内容层级，使用亮白、字号、字重和间距，不再使用靛蓝。

已比较并完成选择的方向：

| 方向 | 优点 | 取舍 |
| --- | --- | --- |
| 琥珀代码，已采用 | 与靛蓝符号区分明显，正文仍然安静 | 新增代码专用色，需要同步现有规范 |
| 保留紫色代码 | 改动较少，延续现有风格 | 紫色与靛蓝接近，需更依赖背景和间距 |
| 全部灰白，仅靠容器区分 | 用色最少 | 扫读时颜色提供的线索较少 |

## 颜色与语义

色值均为不透明 sRGB；名称是语义 token，供编辑器和预览共用。

`md.secondary` 与 `md.syntax` 必须保留为两个独立 token，即使当前色值相同。前者表达内容的次要层级，后者表达 Markdown 语法；后续调整语法标记的亮度时，不应连带改变引用文字或语言标签。

| Token | 用途 | 色值 | 配套规则 |
| --- | --- | --- | --- |
| `md.canvas` | 正文画布背景 | `#09090B` zinc-950 | 编辑和预览一致 |
| `md.text` | 正文、列表项文字、表格内容 | `#D4D4D8` zinc-300 | 列表项整段不染色 |
| `md.heading` | 标题、加粗内容 | `#F4F4F5` zinc-100 | 标题通过字号、字重和间距区分层级，不为每级分配颜色 |
| `md.secondary` | 引用文字、代码语言标签 | `#A1A1AA` zinc-400 | 降低强调程度但保持可读 |
| `md.syntax` | 编辑中可见的 Markdown 分隔符 | `#A1A1AA` zinc-400 | 比正文弱，不能弱到难以辨认 |
| `md.list-marker` | 无序列表符号、有序列表编号 | `#818CF8` indigo-400 | 只作用于符号或编号；不覆盖列表内代码、链接等的样式 |
| `md.link` | 链接 | `#818CF8` indigo-400 | 配合下划线，与同色列表符号区分 |
| `md.code-text` | 行内代码、代码块内容 | `#FCD34D` amber-300 | 两种代码采用同一语义色 |
| `md.code-bg` | 行内代码底色、完整代码块底色 | `#18181B` zinc-900 | 代码块背景覆盖空白和整行宽度，不仅覆盖字符 |
| `md.border` | 代码块、表格等装饰性边框 | `#3F3F46` zinc-700 | 不用于交互控件的唯一边界提示 |
| `md.quote-border` | 引用左边线 | `#52525B` zinc-600 | 配合缩进与引用文字样式 |
| `md.selection-bg` | 编辑选区背景 | `#312E81` indigo-900 | 选区文字统一 `#F4F4F5`，优先于语法色 |
| `md.search-bg` | 搜索命中背景 | `#854D0E` amber-800 | 命中文字统一 `#FEF3C7` amber-100；被选中时选区样式优先 |

代码色表示内容类型，不表示告警；应用级告警仍依靠图标、文字和所在位置表达状态。

## 结构与排版规则

- 无序列表：靛蓝项目符号、灰白正文、清晰缩进。编辑态保留真实列表标记，预览态使用列表圆点；都不能把整条列表染成靛蓝。
- 有序列表：编号遵循列表符号颜色，正文遵循正文色。
- 行内代码：琥珀文字、深灰底色、小圆角；显示性内边距横向约 `0.3em`，纵向不改变行高。不能修改实际文本或插入空格实现视觉样式。
- 代码块：琥珀文字、连续深灰背景、`1px` 装饰边框、`8px` 圆角，内边距 `12px 16px`。列表内的代码块保持这一外观，不继承列表符号色。
- 代码块仍用单一代码文字色；本次不加入按编程语言区分关键字、字符串等的语法高亮。
- 行内代码与代码块必须共用 `md.code-text`，初始值固定为 `#FCD34D`。不为尚未观察到的问题提前拆成两套代码颜色。
- 代码嵌在链接中时，代码文字保持琥珀色，链接下划线保持靛蓝色；如列表中的 ``- See [`getUser()`](...)``，列表符号为靛蓝、普通文字为灰白、代码为琥珀，各层样式不能互相覆盖。
- 引用：次级文字色、左边线和缩进共同表达结构；不能仅靠颜色区分。
- 强调：粗体主要靠字重，斜体主要靠字形，删除线保留横线，不增加新的颜色类别。
- 表格：正文色用于单元格文字，标题色和字重用于表头，装饰边框用于网格。
- 交互与内容分层：链接使用下划线；代码使用容器；列表使用符号和缩进。即便难以区分色相，也保留结构线索。

## 已确认的行内代码标记行为

用户已确认以下交互：

- 编辑器中，光标进入行内代码时显示两侧反引号，离开后隐藏；有选区与该代码片段相交时也显示，便于编辑或删除完整语法。
- 两侧分隔符使用 `md.syntax`，内容使用 `md.code-text`。隐藏只改变显示，存储、复制源文本和导出的 Markdown 仍保留反引号。
- 按实际 Markdown 解析范围识别行内代码，支持一个或多个反引号构成的分隔符；不能通过正则全局隐藏反引号，也不能隐藏代码正文中的字面反引号。
- 点击隐藏后的代码内容，应能把光标放入代码并重新显示标记；键盘移动和选择必须可用，不能改写文档或破坏撤销历史。
- 预览中显示代码内容和样式，不显示形成行内代码的 Markdown 分隔符。
- 本次标记隐藏仅覆盖行内代码；代码块围栏、标题和列表标记不自动加入隐藏范围。

## 对比度校验

设计目标：正文区域所有普通文字与其背景至少达到 `4.5:1`。这是 WCAG 2.2 文本最低对比度的一般要求；此处没有利用大字的较低门槛。[W3C：Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

使用 sRGB 相对亮度计算的结果如下（比值保留两位小数展示，判断使用原始值）：

| 组合 | 对比度 |
| --- | --- |
| 正文 `#D4D4D8` / 画布 `#09090B` | 13.46:1 |
| 标题 `#F4F4F5` / 画布 `#09090B` | 18.10:1 |
| 次级文字 `#A1A1AA` / 画布 `#09090B` | 7.76:1 |
| 链接、列表符号 `#818CF8` / 画布 `#09090B` | 6.67:1 |
| 代码 `#FCD34D` / 代码底色 `#18181B` | 12.29:1 |
| 代码分隔符 `#A1A1AA` / 代码底色 `#18181B` | 6.91:1 |
| 选中文字 `#F4F4F5` / 选区 `#312E81` | 10.39:1 |
| 搜索命中文字 `#FEF3C7` / 搜索底色 `#854D0E` | 6.15:1 |

这些是指定色值组合的计算结果，不代表已经验证了应用最终渲染或整个应用的无障碍合规。实现时需检查实际背景、透明度、样式优先级、选区和搜索叠加后的结果。

## 落地与验收

按本规范同步编辑器主题和预览样式；当前实施计划中的旧色值不能直接沿用。配色方向已确认，无需重新选择。

由共享语义 token 提供颜色，CodeMirror 主题和 `.md-preview` 样式引用相同来源，避免两处独立维护色值。具体实现边界在修订实施计划时确定。

验收样本包括普通段落、嵌套列表、列表内行内代码、列表内代码块、带链接的列表、引用、表格、搜索命中和选区。重点确认：

1. 列表正文与普通段落颜色一致，仅符号强调。
2. 行内代码和代码块与列表明显区分；代码块空行仍有完整背景。
3. 编辑与预览的语义色一致，无颜色覆盖导致的回退。
4. 行内代码在点击、方向键移动、选中和取消选择时正确显示／隐藏标记，文档内容和撤销历史不变。
5. 选区与搜索命中同时存在时，文字保持可读，代码及列表样式不会覆盖选区。
6. 用含至少 30 行代码的笔记检查大面积琥珀文字在桌面和手机上的观感。这是实现后的视觉验收项，不预先降亮度；若实际效果偏亮，再统一调整 `md.code-text` 并重新计算对比度，行内代码与代码块仍共用一个 token。
